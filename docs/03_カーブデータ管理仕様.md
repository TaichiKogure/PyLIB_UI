# カーブデータ管理仕様

設計日：2026-10-14。ユーザー要件「今はダミーデータで模倣し、後から取得する充放電データを入力・管理する」を初期必須機能として扱う。本書は機能仕様であり、データの取得や生成はまだ実施していない。

## 1. データの区別

| 種別 | 意味 | 使用できる目的 |
|---|---|---|
| synthetic_demo | 任意の数式・模擬ノイズによる操作確認用データ | UI、取込、比較、保存、異常入力の確認 |
| simulation | 記録された物理モデルからの計算結果 | 設計比較、モデル間比較、仮想実験 |
| public_measured | 出典が確認できる公開実測 | 公開セル条件での再現・同定・検証 |
| user_measured | ユーザーが取り込む実測 | 対象セルでの校正・検証 |
| digitized | 論文図などから読み取ったデータ | 読取誤差を含む比較。原測定と区別 |

合成データと実測は一覧、凡例、エクスポートで常に区別する。物理ソルバから生成したカーブへノイズを加えた場合は、元SimulationRunとノイズ操作を両方記録する。そのデータを同じモデルで再現できても、実セルの予測精度を検証したことにはならない。

18650/21700 × NCX/LFP × 黒鉛/複合負極の8区分をテンプレート管理上は用意する。ただし8区分すべてに校正済みパラメータが存在するとはしない。操作デモ、既知の公開セル、対象設計の仮パラメータを別テンプレートとする。

## 2. 管理するオブジェクト

| オブジェクト | 内容と関係 |
|---|---|
| Project | 調査目的、設計群、比較セット、単位表示設定 |
| CellDesign | 寸法・巻回構造・集電・境界条件の版付き設計 |
| MaterialRecipe | NCXの組成、LFP、黒鉛、Si、SiOx、電解液の識別と配合 |
| ParameterSet | 材料関数・モデル係数・出典・適用範囲。設計値と分離 |
| CellSpecimen | 実セル個体ID、製造ロット、履歴、分解情報、対応設計 |
| Experiment | 試験条件、サイクラー、センサ、校正、試験日、試料 |
| CurveDataset | 原本・正規化データ・取込条件・データ種別・出典 |
| CurveSegment | 充電/放電/休止、サイクル、ステップ、選別マスク |
| SimulationRun | 入力snapshot、エンジン・版、計算条件、結果、終了理由 |
| FitRun | 使用データ、学習/検証区分、推定変数、結果候補、採否 |
| ComparisonSet | 比較するデータID、軸、単位、整列法、表示範囲 |

一つの設計に複数の実セルが属し、一つの実セルに複数の実験が属する。設計名やファイル名だけをキーにしない。元の設計を編集しても過去計算の入力snapshotは変わらない。実験の材料情報が不明な場合、形状が似たテンプレートを自動で紐付けない。

## 3. 最初に実装する取込と入力

最初はCSV/TSVと表への貼付け・手入力を提供する。ファイルを選び、列と単位を対応付け、プレビューと検査結果を確認して保存する。一般的なサイクラー形式が判明した後で[PyProBE](https://github.com/ImperialCollegeLondon/PyProBE)または[cellpy](https://github.com/jepegit/cellpy/blob/master/README.md)のローダーを追加する。

Excelファイル取込は次段階で、シート選択・ヘッダ行・単位を明示する。EIS、画像からのカーブ読取、装置とのオンライン接続は後続機能とする。最初から特定メーカーのCSV列名に固定しない。

### データ形態ごとの最小情報

| 形態 | 必須列の例 | 制約 |
|---|---|---|
| 時系列充放電 | 時間、電圧、電流 | 電流符号と時間基準が必要 |
| 容量–電圧カーブ | 容量、電圧、充放電区分 | 時間・電流がなければ動的同定の対象にしない |
| SOC–OCV | SOC、電圧、測定/推定方法 | SOC基準、休止条件、温度、履歴を記録 |
| 温度併記 | 時間、温度、センサ位置 | 表面・中心・雰囲気を混同しない |
| EIS（後期） | 周波数、実部、虚部 | 符号、単位、SOC、温度、振幅を記録 |

容量–電圧だけのデータも保存・表示できるようにし、欠けた時間や電流を勝手に補わない。条件の不足で同定できない場合も、データ管理自体は可能にする。

### 正規化カラム案

`dataset_id, segment_id, time_s, voltage_V, current_A, capacity_charge_Ah, capacity_discharge_Ah, temperature_K, cycle_index, step_index, quality_flag`

列はデータ形態に応じてnullableとする。未測定値を0で埋めない。複数の温度センサや補助チャンネルは別テーブルでセンサID・時刻・値・単位を保存する。原本に含まれる未使用の列も破棄しない。

アプリ内部の電流符号は「放電を正、充電を負」に統一する案とし、原本の符号と変換規則を保存する。電流の絶対値だけから充放電を推定しない。時間は試験相対時間と絶対timestampを区別し、ステップごとに0へ戻る時間を実験全体の経過時間と誤認しない。

## 4. 取込時の品質検査

| 項目 | 処理 |
|---|---|
| エンコード・区切り・小数点 | UTF-8等を候補表示し、プレビューで確定。小数カンマを列区切りと混同しない |
| 単位 | mV/V、mA/A、mAh/Ah、℃/K、秒/分/時間を列単位で指定 |
| 時間 | 区間内の逆転、重複、欠落、計測間隔、区間のリセットを検出 |
| 数値・欠損 | NaN、無限値、文字混在を行番号付きで表示。欠損率を記録 |
| 容量 | 電流積分と装置容量を比較。符号、リセット、積分区間を確認 |
| 条件 | 電圧終止値、温度、セルID、容量基準が欠ける場合は未指定のまま保持 |
| 重複ファイル | 原本ハッシュで検出。別試料の同一形式データは内容・来歴で判断 |
| 外れ値 | 候補表示し、マスクとして記録。黙って削除・平滑化しない |

0 Aの休止を欠損と扱わない。電圧プラトーを重複データとして間引かない。ソート、補間、平滑化、サイクル抽出、単位変換は変換履歴として保存する。自動修正の提案は原本を変更せず、プレビュー後に正規化版として確定する。

同時刻に複数のステップ境界値が記録される形式もあるため、時刻重複は常にエラーとはしない。原本の行順・ステップ番号と合わせて判断する。容量の積分は時間のリセット区間を跨いで行わない。

## 5. 一覧・検索・比較

一覧では、名称、データ種別、セル寸法、正負極、温度、電流/Cレート、サイクル範囲、出典、品質状態、作成日を表示する。未知の項目は「不明」とし、検索フィルタから除外されない選択肢を設ける。保存データ、計算結果、同定結果を関連付けて辿れるようにする。

比較画面は、時間–電圧、容量–電圧、SOC–電圧、時間–温度、容量保持率を優先する。次の規則を明示する。

- 絶対容量Ahと比容量mAh/gを区別し、質量が活物質・電極・セルのどれか表示する。
- SOCは公称容量基準・測定容量基準・モデル内部状態を区別する。電極化学量論θとセルSOCを混同しない。
- 時間ゼロや容量ゼロの整列、容量正規化、オフセット補正は操作として明示し、比較セットへ保存する。
- 容量差を調べる比較では各カーブを自動で0–100%へ揃えない。
- 共通範囲だけの誤差と、片方にしか存在しない末尾の長さを併記する。途中打切りを低誤差に見せない。
- 同じ充放電区分、温度、休止履歴を優先して比較する。補間法と評価点を保存し、外挿は既定で行わない。

初期指標は電圧RMSE/最大絶対誤差、容量差、エネルギー差、終止時刻差とする。温度はセンサ位置が対応する場合だけ比較する。dQ/dV、dV/dQは後期に加え、微分前の平滑化条件・低傾斜区間の数値不安定性を表示する。

## 6. 公開データによる初期検証

第一候補は[ChenらのLG M50公開データ](https://zenodo.org/records/4032561)である。公開ページでcell02/03/04のCSVと、CC-CV充電・複数レート放電、電流・電圧・温度データの説明を確認した。まだダウンロード・列検査・再現計算はしていない。

[原著論文](https://doi.org/10.1149/1945-7111/ab9050)の21700・NMC811/黒鉛–SiOxという条件を保って再現する。これを18650、LFP、純Si混合、全面集電構造の実測へ読み替えない。公開セルの再現に成功してから、設計変更による計算結果を仮説として比較する。

LFPなどのパラメータ候補として[About:Energyの公開BPX](https://github.com/About-Energy-OpenSource/About-Energy-BPX-Parameterisation)も確認した。ただしパラメータファイルと独立した検証用時系列実測は別資産であり、同一に数えない。取得時には対象セル、測定条件、ライセンス、再配布条件、原本ハッシュを記録する。

将来集める実測は、少なくとも異なるレート・温度、CC/CV/休止、複数個体を含める。析出、膨張、応力については電圧カーブだけで検証を完結させず、対応する追加計測を段階的に用意する。

## 7. 同定と検証を分ける

PyBOPの導入時は、まず容量・抵抗・少数の輸送係数など感度を確認できる変数に限定する。材料名、組成、初期Li在庫、温度、厚み等を同時に自由化すると、異なるパラメータが似たカーブを作り得る。

同定用と検証用の区分はFitRunの開始前に固定する。時系列点を無作為分割するだけでは隣接点の情報が共有されるため、セル個体、試験条件、サイクル、温度の単位で分ける。同じ測定から推定したパラメータを、その測定で独立検証したとはしない。

目的関数は用途に合わせ、電圧・温度・容量の重みと単位の正規化を明示する。測定ノイズが分かれば不確かさに基づく重みを使う。単に高密度な時系列だけが支配しないよう、試験間の重みも設定する。

推定結果にはパラメータ範囲、感度、相関、境界張り付き、初期値依存を保存する。信頼区間・事後分布は実際に算出した場合のみ表示する。良いフィットであっても識別可能性が不足する変数は「推定不確実」とする。[PyBOP](https://github.com/pybop-team/PyBOP)

同定は新しいParameterSet候補を作る。自動で全プロジェクトの既定値を上書きせず、比較結果を見て採用すると版が進む。どの実測に合わせた値かを、以後の計算結果から追跡できるようにする。

## 8. 保存形式と再現性

ローカル初期構成は次を提案する。

```text
project/
  project.sqlite           # ID、関係、注釈、版、ジョブ状態
  raw/<dataset_id>/        # 取り込んだ原本、原本メタデータ
  normalized/<dataset_id>/ # 正規化Parquet、変換履歴
  designs/<version_id>/    # 設計snapshot
  parameters/<version_id>/ # パラメータsnapshot・出典
  runs/<run_id>/           # 条件JSON、時系列、必要な場データ、診断
  fits/<fit_id>/           # データ分割、目的関数、推定結果、採否
  exports/                # 明示的に生成したCSV・レポート
```

rawは取込時のSHA-256と一致する状態で保持する。正規化・加工結果は派生物とする。関数を含むパラメータは、任意コードを保存して自動実行する形式ではなく、登録済み関数IDと係数、または単位付きテーブルを基本にする。

例としてデータのメタデータには次を持たせる。以下はスキーマ例であり、存在する実測や実行済みジョブの記録ではない。

```json
{
  "schema_version": "0.1-proposal",
  "dataset_id": "example-dataset-id",
  "source_kind": "synthetic_demo",
  "cell_format": "21700",
  "cathode_family": "NCX",
  "cathode_composition": null,
  "anode_materials": ["graphite", "Si"],
  "raw_sha256": null,
  "source_url": null,
  "license_id": null,
  "normalization": {
    "current_positive": "discharge",
    "time_unit": "s",
    "capacity_unit": "Ah"
  },
  "validation_status": "demo_only"
}
```

プロジェクトのバックアップと移動は、SQLiteと参照ファイルを一緒に扱う。書込み中の不整合を避けるスナップショット出力を設け、復元後にリンクとハッシュを検査する。削除は参照中データを検出し、まずアーカイブ扱いにする。

## 9. 初期版の受入条件

1. CSV/貼付けの列対応と単位を指定して取込でき、原本・正規化・来歴が保存される。
2. 時系列と容量–電圧だけのデータを区別して登録できる。
3. 充放電符号、時間リセット、単位違い、欠損、重複ファイルを検出できる。
4. 保存した比較セットを再表示でき、正規化・整列条件が復元される。
5. 合成データが実測として表示・出力されない。
6. 設計やパラメータを編集しても過去計算・過去同定の条件が変わらない。
7. 再起動・バックアップ復元後も原本・注釈・計算との関連を辿れる。

これらは今後の実装完了条件であり、現時点で合格した検査結果ではない。
