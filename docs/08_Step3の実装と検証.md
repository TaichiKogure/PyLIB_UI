# Step 3 — 物理計算・永続ジョブ・比較の実装と検証

更新日：2026-10-15（日本時間）。基本版v0.4。Step0の固定研究環境を使い、画面から実際のPyBaMMソルバを別プロセスで実行する。

## 1. 起動と対応範囲

通常は `start.ps1` で起動する。起動中の旧サーバーは終了して再起動し、画面を再読込する。画面サーバー自体にPyBaMMをインストールする必要はない。既存のPython
3.14 `.venv` と、計算用Python 3.13 `.venv-research` を分離する。

計算環境の再現は [Step0・1の手順](06_Step0_1の実装と検証.md)。起動時にPython 3.13、PyBaMM 26.10.1.0、pybammsolvers
0.11.1、NumPy 2.3.5、CasADi 3.8.1を確認する。環境がない／固定版と異なる場合は物理計算を無効にして理由を表示する。基本ライブラリと合成モデルは引き続き使用できる。

別パスの同じ固定環境を使う場合：

```powershell
.\.venv\Scripts\python.exe main.py --research-python 'G:\別の固定環境\Scripts\python.exe'
```

| 材料セット                   | SPMe | DFN  | 熱           | 保存設計の条件                         |
|------------------------------|------|------|--------------|----------------------------------------|
| Chen2020                     | 対応 | 対応 | 等温／集中熱 | NMC811、黒鉛単相、注液充填率1          |

組合せの対応は短時間の機能検査である。任意のレート・形状・温度での精度保証ではない。物性セットの引用IDはChen2020、複合負極はChen2020＋Ai2022。結果にセット名・パッケージ版・引用ID・上書き値を保存する。参考：[PyBaMMの実験ステップ](https://docs.pybamm.org/en/pybamm-v26.10.0.0/source/api/experiment/experiment_steps.html)、[Chenらの原著](https://doi.org/10.1149/1945-7111/ab9050)
。APIは実際にインストールした固定版でも確認した。

## 2. UIの操作

1. プロジェクトを選ぶ。画面上部の「SPMe・DFNの試験」リンクでStep3へ移動する。
2. 計算名、SPMeまたはDFN、物性セットを選ぶ。複合セットはDFN等温へ限定する。
3. 「計算に使う設計」で、文献セットの基準形状、またはStep2で保存した対応設計を選ぶ。Step2の「合成モデルの試験条件へ反映」は従来ECM用であり、Step3はこの選択欄を使う。
4. 初期SOC、温度、電圧範囲を指定する。等温では周囲温度に固定する。初期温度と周囲温度の差による緩和を見る場合は集中熱を選ぶ。
5. CC・CV・休止を並べる。電流は放電＋／充電−。CCは電流Aと上限秒、必要なら終止電圧V。CVは保持電圧V、上限秒、終止電流の絶対値A。休止は上限秒。
6. 電流プロファイルを使う場合は入力方法を切り替え、ヘッダなしの `秒, A` を貼り付ける。先頭は0秒、重複なし昇順、2〜2000点、直線補間。ステップ試験との混在は未対応。
7. 「出力・数値精度・時間上限」で出力間隔、粗／標準／細メッシュ、許容誤差、実時間上限を設定する。
8. 「物理計算ジョブを追加」で開始する。別プロセスで1件ずつ実行し、待機＋実行中は最大8件。画面の入力を後から変更しても登録済みジョブは変わらない。
9. 完了・一部結果は自動保存する。「結果を表示」でカーブ、統計、来歴を確認できる。結果は電圧・電流・温度・容量・電荷帳簿SOCを持ち、CSV／条件付きJSONで書き出せる。
10. 保存一覧のチェックで他の物理計算・取込データと比較する。比較セットも従来と同じ方法で保存できる。「条件を復元」は計算時のスナップショットを入力へ戻す。再実行は新しいジョブ・結果になる。

UIの初期例は1A放電30秒→休止10秒→1A充電30秒、初期SOC0.5、25°C。CCからCVへの例は、初期SOC0.5、CC −1A・3600秒上限・4.0V終止 → CV
4.0V・300秒上限・0.1A終止。この条件ではCC終止イベントからCVへ移行することを実行確認した。

電圧範囲に達したCC／プロファイルのステップはイベント終了して次へ進む。最初から終止条件を満たすステップは `skip_ok=False`
でエラーとし、黙って省略しない。これは実機の充放電器を制御する機能ではない。

## 3. 設計から物理計算への変換

文献セットを基礎に、保存設計の電極片面厚、箔、セパレータ、空隙率、相体積分率、両面の有効面積、Cレート基準容量を渡す。等価面積は
`正極塗工幅×巻回長×並列面数2`。面積の二重計上を避け、負極の余剰幅は1D重なり面積に縮約する。

黒鉛単相は1相、複合負極は黒鉛をPrimary、SiをSecondaryに対応する。Si=0では単相セットを使う。反応・拡散・OCV・最大濃度などは文献セットを保持する。配合から相分率へ換算する密度はStep2の仮定値に依存するため、設計反映後は対象セルとして未校正の仮想計算である。

集中熱では円筒の外形体積と外表面積、熱伝達係数を反映する。熱物性は文献セットから引き継ぐ。端面接触率から抵抗や発熱を自動生成しない。局所分布、析出、SEI、劣化、粒子・缶の力学はこの段階に含めない。

初期SOCをPyBaMMの電極SOH初期化へ渡す。Step2の任意の初期Li充填率は転用しない。文献パラメータの数値スナップショットはSOC初期化前であるため、実際の初期粒子表面化学量論とLi在庫を別項目
`initial_state` に保存する。`lithium_balance` は粒子＋電解液の初期・終了Li量を記録する。

出力の `soc` は `初期SOC − 符号付き通過容量 / Cレート基準容量`
の電荷帳簿であり、相別化学量論SOCと同一ではない。範囲外も0〜1に切り捨てない。絶対通過容量・符号付きエネルギーはPyBaMMの積分状態を使用し、疎な表示点で再積分しない。ステップ境界では区間IDを分け、電流ジャンプを誤って直線接続しない。

## 4. ジョブ・保存・障害時の扱い

`physics_jobs` テーブルへ入力・設計版・状態を保持する。成功結果は既存 `runs` テーブルへ保存する。作業ファイルは
`data/physics-jobs/<job_id>/`。入力JSON、原子置換した出力JSON、ローカル診断ログを置く。ブラウザーには第三者ライブラリの生の例外文やログを返さない。

状態は `queued → running → completed / partial / failed / cancelled / timeout / interrupted`
。取消は実プロセスを終了する。時間上限はモデル構築・初期化・計算・出力を含む実時間。取消と時間超過では確定結果を作らない。正常な終止イベントとソルバ失敗を区別し、PyBaMMが部分解を返した場合は
`partial` として保存する。強制停止時の途中解は未保存。ステップ途中からの再開も未対応。

サーバー終了・再起動で残った待機／実行中ジョブは中断扱いにする。自動再実行しない。「条件を復元」で新しいジョブを作る。同じ保存先の計算コントローラはファイルロックで1つに制限する。別保存先での起動は可能。バックアップはサーバー停止後にdataフォルダー全体をコピーする。

APIは `GET /api/physics/config`、`GET /api/jobs?project_id=...`、`POST /api/jobs`（project_idとinput）、
`POST /api/jobs/cancel`（project_idとid）。実行パス・任意コード・コマンドはHTTPから受け取らない。結果と出力は既存
`/api/results/<id>[.json|.csv]` で取得する。

## 5. 検証結果

[回帰テスト](evidence/step03/unittest.txt) は **39件成功**
（従来33件＋入力・材料制約、取消・上限・再起動・単一起動、HTTPの6件）。通常のHTTPテストは専用DB・TEMP/TMPを `.test_tmp`
に指定し、Windowsのローカル通信制限を受けない許可された実行経路で行った。OSの設定は変更していない。

[実ワーカー統合検証](evidence/step03/integration.json)
は15ケース。14ケースの完了と、意図した初期終止条件エラー1件を確認した。SPMe、DFN、集中熱、DFN複合、CV、CC→CV、電流プロファイル、設計反映した単相SPMe／DFNと複合DFNを実行した。各ケースの条件・数値結果は同フォルダーのJSONに保存。1A放電30秒＋1A充電30秒の絶対通過容量は1/60Ah、最終電荷帳簿は0.5。プロファイルの解析的積分も確認した。

[初期状態・Li帳簿](evidence/step03/initial-state.json)
は単相と複合の実計算で確認した。粒子＋電解液Liの相対変化は単相で約1.9e-16、複合で約4.6e-8。析出・副反応を入れていない短い閉鎖系の数値収支である。

[実プロセスの状態検証](evidence/step03/worker-lifecycle.json)
では、DFN・細メッシュの長いプロファイルを約5.06秒で実時間上限停止し、取消・終了／再起動での中断も確認した。いずれも成功結果を作っていない。単体テストのsleepワーカーだけを根拠にしたものではない。

ブラウザーではSPMe・DFNの実行と自動保存、同条件比較、保存設計をDFNへ渡す導線、条件復元、実ジョブの取消、サーバー再起動後のジョブ・結果復元を確認した。公開実測6,315点・24区間を専用テストプロジェクトへ登録し、SPMeと同じ図へ表示した。これは[表示比較の証跡](evidence/step03/public-comparison.png)
で、試験条件・初期状態を合わせていないため、予測精度やRMSE・校正の証明ではない。利用者の既存DBは変更していない。

さらにUIで電流プロファイルとCV
3.8Vの編集→実行→完了、SPMeとDFNの注釈付き比較セット保存を確認。[物理計算の比較画面](evidence/step03/physics-ui.png)
を保存した。320px幅でdocumentのclientWidth／scrollWidthはともに305px（スクロールバーを除く）で一致し、横はみ出しなし。app.js／library.js／design.js／physics.jsの構文検査も成功した。

Step3の基礎導線は対応表の範囲で利用できる。LFP/NCA/SiOxの物性セット、対象セルの実測条件との整合・校正、任意設計でのメッシュ収束、長期劣化、全材料組合せ、速度・メモリの統計評価は残る。M1の全対象材料の物理精度やStep0〜3の全検証条件が満たされたという意味ではない。
