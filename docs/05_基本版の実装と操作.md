# PyLIB UI 基本版 v0.1 — 実装・操作・検証

実装日：2026-10-14（日本時間）。まずUIと保存・比較の一巡を動かす軽量版。既存設計資料01〜04は将来計画として維持する。

## 1. 今使える機能

- 18650／21700の編集可能な初期値、外径・高さの模式図。
- NMC／LFPの **合成フルセルOCV**。材料の具体組成・粒子・複合負極は未対応。
- 単一ステップの定電流放電、定電流充電、0 A休止。
- 基準容量・Cレート・初期SOC・温度・抵抗・RC時定数・熱条件の編集。
- 電圧・SOC・セル平均温度・電流の時系列。横軸は時間／通過容量。
- 電圧／SOC／設定時間での終了、終了理由の表示。開始時に終止条件を満たす場合は0秒終了。
- 明示的な結果保存、保存一覧（最新100件）、表示・条件復元、最大3件との比較。
- UTF-8 BOM付きCSVと、入力・時系列・モデル版・制約付きJSONのダウンロード。
- 入力変更時の「再計算待ち」、過去結果の入力snapshot表示。

実セルの精度を保証するパラメータではない。寸法は **表面積と対流放熱だけ**に反映し、容量・抵抗・熱容量は独立入力である。UIに表示する制約をJSONにも保存する。

## 2. 起動と操作

Python 3.10以上。標準ライブラリだけで動作する。既存 `.venv` のPython 3.14.0で検証。

```powershell
cd G:\PyLIB_UI
.\start.ps1
```

ブラウザーが開かない場合は `http://127.0.0.1:8765` を開く。PyCharmでは `main.py` を実行する。終了は起動コンソールの
`Ctrl+C`。ポート使用中なら ` .\start.ps1 -Port 8767` のように変更する。

1. セル形式と模式曲線を選ぶ。形式切替で寸法・容量・抵抗・熱容量の初期値が変わるので確認する。
2. 計算名・モード・Cレート・初期SOC・時間・周囲温度を設定する。充電選択は初期SOCを20%、放電選択は95%に戻す。手動編集した計算名や保存条件を復元した名前は保持する。
3. 必要なら「モデル・詳細条件」を開く。LFP選択では電圧初期値を2.5–3.65 Vへ変更する。初期温度と周囲温度は独立。
4. 「シミュレーションを実行」。電圧・SOC・温度・電流タブ、横軸を切り替える。
5. 気に入った条件は「結果を保存」。自動保存ではない。CSVは時系列と来歴コメント、JSONは条件と制約を含む完全な結果。
6. 保存一覧のチェックを入れると重ね合わせ。表示ボタンは結果のみを切替。「この結果の条件を復元」で入力へ戻す。

保存先の既定値はプロジェクトの `data/runs.sqlite3`。独立した環境を使う場合：

```powershell
.\.venv\Scripts\python.exe main.py --no-browser --port 8767 --data-dir G:\PyLIB_UI\data\project_a
```

未保存結果はサーバー内の直近20件のみ保持し、再起動で消える。保存後は再起動しても保持する。同じ計算IDの保存は重複を作らない。バックアップはサーバー停止後に
`data` フォルダーをコピーする。

## 3. 計算の意味

時間はs、電流はA、抵抗はΩへ変換して計算する。UIの抵抗入力はmΩ。

```text
I = sign × C_rate × Q_ref [A]（放電 +1、充電 −1、休止 0）
dSOC/dt = −I / (3600 Q_ref)
dV_RC/dt = (I R1 − V_RC) / tau
V_terminal = OCV(SOC) − I R0 − V_RC
C_th dT/dt = I² R0 + V_RC²/R1 − h A_surface (T − T_ambient)
A_surface = π d H + π d²/2
```

初期分極は0 V。R1=0のときRC発熱は0、h=0のとき断熱。OCVはSOC 0–1のみに定義する以下の模式式で、公開材料フィットではない。

```text
NMC: 3.0 + 1.1 SOC + 0.1 tanh(12(SOC−0.5))
LFP: 3.25 + 0.12 SOC + 0.22 exp(−30(1−SOC)) − 0.35 exp(−30 SOC)
```

SOC・RC分極は一定電流下の解析更新。RC抵抗の発熱積分を計算し、その時間区間の平均発熱と指数関数的放熱で温度を更新する。電圧／SOC終止点は二分探索して、出力間隔を超えた過放電・過充電点を記録しない。エネルギーは端子電力の台形積分。通過容量は電流絶対値の積算で、公称容量や設計算定容量と区別する。充電エネルギーは負、放電は正。

出力間隔1–60 s、試験時間0.1–360 min、最大12,001点。有限値・範囲・電圧上下関係をサーバーでも検査する。温度の電気特性へのフィードバック、可逆熱、休止前の履歴連結はない。

## 4. ファイル構成と拡張方法

```text
main.py                  起動入口
start.ps1                Windows起動補助
pylib_ui/schema.py       型・単位付き共通入力と検証
pylib_ui/models.py       ModelOutput / SimulationModel / モデル登録
pylib_ui/service.py      実行・来歴・一時保持・エクスポート
pylib_ui/storage.py      SQLite結果保存
pylib_ui/server.py       loopback HTTP APIと静的ファイル配信
pylib_ui/static/         日本語UI・SVGグラフ
tests/test_simulation.py 計算・保存・HTTPの回帰確認
```

`SimulationModel` の `id/version/label/source_type/validation_status/limitations` と `simulate(config) -> ModelOutput`
がエンジン接続点。モデルを `MODEL_REGISTRY` に登録すると、`/api/config` 経由でUIのモデル選択に現れる。保存・HTTP層を作り直さずに追加できる。

拡張する順序：

1. PyBaMM用アダプタを追加。公開パラメータセットとセル設計を区別し、SPMe基準ケースを検証する。必要な入力だけ共通スキーマとUIへ追加し、無視する入力を表示する。
2. 実測CSVの取込・単位・原本・出典を追加。`schema_version` を更新し、既存snapshotを移行してから異なる種別を一覧・凡例で識別する。現UIは合成結果のみ。
3. CC/CV／複数ステップの試験スキーマ、非同期worker、進捗・取消を追加。基本版の高速計算は同期API。
4. 物性・設計収支、全面集電、複合負極、析出、熱分布・力学を検証済み範囲ごとに追加。

現在のSQLiteは自己完結したJSONを保存。原本ファイル・大規模時系列は未対応なので、必要な段階で設計資料03の分離保存へ進む。新しいエンジンが時系列変数を増やす場合は単位辞書・エクスポートとグラフ選択肢も拡張する。

API：`GET /api/config`、`POST /api/simulate`、`POST /api/save {id}`、`GET /api/runs`、`GET /api/results/{id}`、同URLの
`.csv` / `.json`。JSON入力、最大64 KiB。127.0.0.1に限定して待受けし、ホスト・Originを検査。外部CDNやオンライン計算への依存はない。
