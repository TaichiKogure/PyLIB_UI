# PyBaMM機能拡張 P1実装と検証

実施日: 2026-10-17。固定研究環境はPyBaMM **26.10.1.0**
を維持した。資料11のP1を実装し、P2の結果変数・分布・実測残差への接続基盤を整えた。P0以前の未コミット変更と保存データは保持している。

## 追加した機能と使い方

更新前のサーバーが起動中の場合は起動コンソールで終了し、`PyLiBStudy.lnk` または `start.cmd` から起動し直す。

1. **SPM / SPMe / DFN**
   を選び、物性と保存設計を指定する。Chen2020は3モデルの等温・集中熱に対応し、Chen2020_compositeはDFN・等温に限定する。登録済みのモデル・物性・熱・ソルバは7組合せとなった。
2. 試験テンプレートを展開するか、ステップを追加する。展開は試験欄を置き換える操作であり、そのまま計算は開始しない。
3. 必要に応じて全体サイクル数、繰返しブロック、各ステップの温度・出力周期・タグ・スキップ許可を編集する。
4. **プレビューを更新**し、展開順序、A/C-rate、終了設定、時間上限、出力数を確認する。
5. ジョブを実行する。進捗欄にはサイクル・ステップ・到達数・試験時刻を表示する。結果と条件は自動保存され、再読込・条件復元ができる。

| 機能             | 実装内容                                                                                   |
|------------------|--------------------------------------------------------------------------------------------|
| SPM              | 既存のSPMe/DFNと同じ登録表・入力欄・ジョブ・結果表示を利用                                 |
| A / C-rate       | 独立したCC種別を選択。プレビューはAとC-rateを併記。CV終止電流もAまたはC-rateで指定         |
| CCCV             | −0.2 Cで4.0 Vまで充電し、4.0 V保持を0.05 Cで打切り、休止する編集可能な例示条件             |
| HPPC型           | 放電パルス・休止・充電パルス・休止の繰返し。規格認証・抵抗指標の算出は含めない             |
| GITT型           | 小電流パルスと緩和の繰返し。拡散係数の同定は含めない                                       |
| CP / CR          | 代数制御・明示制御・定義済みの微分追従制御。電圧によるステップ終了と電流上限イベントを設定 |
| 波形             | 0秒始まりの時間・電流を直線補間。単独の波形入力と、他ステップ／繰返しへの混在に対応        |
| 繰返し           | 試験全体のサイクルと入れ子の繰返しブロック。画面で追加・編集・復元できる                   |
| 開始日時         | 試験の最初のステップにISO日時を設定。時刻ラベルであり、実行予約や実時間待機ではない        |
| 温度・周期・タグ | 各ステップで指定可能。空欄の温度・周期は全体設定を継承。温度は周囲温度の境界条件           |
| スキップ         | 既定は不可。初期条件で終止済みのステップを明示許可した場合だけスキップし、結果に状態を記録 |

テンプレートの時間は最大値で、開始SOCや材料・設計により実際の到達時間は変わる。CCCVを繰り返して充電し続けると、次のCCステップが初期状態で終止済みとなることがある。用途に合わせて放電ステップを加える等の編集が必要。

## 容量・電流・制御の意味

C-rate基準容量は、保存設計がある場合はその設計の `c_rate_reference_ah`、ない場合は文献セットの
`Nominal cell capacity [A.h]` を使う。現在のChen2020 / Chen2020_compositeはいずれも5
Ahであり、ワーカーでも実際の物性容量とプレビュー値の一致を確認する。設計容量・文献容量・実測容量を混同しない。

- 換算式: `I [A] = C-rate × 基準容量 [Ah]`。逆換算は `C-rate = I / 基準容量`。
- 電流・C-rate・電力は放電が正、充電が負。CRの負値は受動抵抗ではなく、能動的な充電制御を表す。
- 代数CP/CRはPyBaMM標準のpower/resistanceステップを使う。
- 明示CPは `I = P/V`、明示CRは `I = V/R`。電圧の循環参照を避けるため、その試験を含む場合だけ `voltage as a state = true`
  を自動適用する。「明示」は電流式の表現であり、ソルバは引き続きIDAKLUである。
- 微分CP/CRは、上記目標電流に対して `dI/dt = (目標電流 − I) / tau` とする定義済み追従制御。時定数を0.1〜60秒で指定する。初回の電流状態は0
  A、切替時は引継ぎ可能な電流状態を利用する。瞬時に目標電力・抵抗を満たす制御とは異なる。

任意Python関数の入力欄は追加していない。定義済みの制御式だけをローカルの信頼済み登録クラスから構築する。

## 入力・保存・上限

条件スキーマを **1.1**、カタログを1.1、物理アダプタを1.3.0にした。版なしと1.0条件は復元時に非破壊で移行し、`cycles=1`、
`start_time=null`等を補う。旧結果のJSON・点列を更新保存する処理は追加していない。

`pylibstudy/protocol.py` が検証・展開・換算・プレビュー・テンプレートを担当し、HTTPとワーカーの両方で使用する。
`experiment_runtime.py` が固定版のExperiment・ステップ・Callbacksを構築する。`POST /api/physics/preview` は
`{input, project_id}` を受け取り、設計の所属・互換性も確認する。プレビューだけではジョブを作成しない。

- 各入力ブロック1〜20項目、繰返し1〜20回、入れ子3階層、全体1〜20サイクル。
- 展開後200ステップ、合計6時間、出力約12000点以内。細かなステップ周期も含めて出力上限を見積もる。
- 電流は±25 A以内。C-rateは容量換算後にも確認する。CP/CRも電圧範囲内で電流上限を守る値に制限する。
- 波形は2〜2000点、時間は重複なしの昇順で0秒始まり。欠損をゼロ埋めしない。
- ステップ温度0〜45°C、出力周期0.1〜60秒。タグは8件以内、各1〜40文字。
- 開始日時は最初のステップのラベルのみ。将来の日時ごとの自動実行や、個別ステップ間の予定時刻による休止挿入は提供しない。

結果には、元の繰返し構造、展開元パス、プレビュー、各ステップの実際の時刻・終了理由・completed/skipped/not_run、Callbacks到達履歴を保存する。PyBaMM側の開始日時、タグ、周期、温度も
`experiment_metadata` に保存する。従来の設定ハッシュ・物性出典・設計版・数値条件・SOC帳簿の区分を継続する。

進捗はCallbacksの実際のサイクル／ステップ到達を原子的な小さなJSONでワーカーからコントローラへ渡す。
**到達数は残り実時間の割合ではない**。モデル構築中はジョブ単位の計算中表示、解の終了後は結果整理と表示する。取消・時間上限・中断時は確定結果を保存しない。状態継続・部分解からの再開はP5の範囲。

## 検証記録

- 全回帰 **93件成功**（最終34.452秒）。新規の6件にはネスト展開・上限・温度等の入力検証、A/C-rate相互換算、設計容量・CV打切り換算、旧版移行、波形混在、プレビューのプロジェクト分離を含む。
- ブラウザー **18件成功**:
  P1専用5件、計算タブ9件、カタログ／環境診断4件。実ジョブのSPM計算、2サイクルの進捗到達、グラフ表示、条件復元まで確認した。デスクトップと390px幅のモバイル表示を目視確認し、ページ全体の横はみ出しも検査した。
- [P1実ソルバ25ケース](evidence/p1/solver-integration.json):
  登録済み7組合せ、SPM/SPMe/DFN/複合DFNでの制御切替4ケース、CCCV/HPPC/GITT、入れ子と日時・温度・タグ・周期、許可スキップ／禁止スキップ／全スキップ、保存設計のC-rate、CP/CR各3制御の電圧打切り6ケース。充放電符号、実際の電力／抵抗、終了イベント、到達数、条件再読込を検査。
- CCCVではCCが4.0 V、CVが0.25 Aで終了することを確認。時限による終了とイベントによる終了を混同しない。
- [既存の実ソルバ15ケース](evidence/p1/step3-regression.json):
  メッシュ・許容誤差・再実行・SPMe/DFN・熱・複合負極・CV・手組みCCCV・電流波形・保存設計・初期条件不成立と、保存結果の再読込を再検証した。
- [実ワーカーのライフサイクル](evidence/p1/worker-lifecycle.json): 時間上限、取消、再起動による中断の3経路が成功し、偽の結果が保存されないことを確認した。
- Pythonコンパイル、変更したJavaScriptの構文、`git diff --check` が成功。

途中で次の問題を再現・修正した。

1. 明示CP/CRで電圧・電流の循環参照が起きたため、必要な場合のみ電圧状態変数を使用するようにした。
2. 固定版のCustomStepのモデルキャッシュキーが制御関数の違いを含まず、同じ試験内のCPとCRが同一モデルとして扱われた。登録クラスでコピー時の型と、制御種別・値・時定数を含むキーを保持し、切替後の電力／抵抗を実ソルバで検証した。
3. PyBaMMの `skip_ok=False` だけでは複数ステップ中の初期条件スキップを全面的に抑止できなかった。アプリ側でもCallbacksで禁止スキップ時に直ちに失敗させ、出力側でも確認するようにした。
4. CCCVの初期例示時間ではSPMのCC/CVが時限で終わったため、時間上限を調整し、イベントによる終了を確認した。
